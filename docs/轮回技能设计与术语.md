# 轮回技能设计与术语

日期：2026-11-03。扩展版本：1.1.0。本次读取手机文件，未写入手机文件或操作游戏界面。手机 `game/update.js` 标记为 1.11.5.2。

## 玩家规则

神左慈与神左慈改均新增 `tyj_lunhui`（轮回）：

> 每轮游戏开始时，你可以选择以下一项执行，然后删除此项：1.随机获得一个觉醒技；2.随机获得一个使命技；3.随机获得一个限定技；4.随机获得一个主公技。

这里“随机获得”按用户定义执行：从所选类别随机展示至多三个不同的技能，玩家选择其中一个获得；不是系统随机强制给一个。

- 可以取消本轮发动，保留全部未使用选项。
- 每名角色每轮至多执行一项。四个选项各自整局只能成功执行一次，删除状态互不共享。
- 先选类别、再选技能，成功获得后删除类别。四类均已删除后不再询问。
- 没有候选的类别暂不显示、不删除；候选只有一个或两个时展示实际数量。
- 失去轮回再获得时，已删除选项不会恢复；下一局的新角色对象有新的记录。
- 获得的是原技能本身，保留原技能发动条件、初始化与次数限制。不会立即觉醒、自动完成使命，也不会恢复已消耗的限定技。

## 术语与源码对应

| 术语 | 规则含义 | 当前版本写法或依据 |
| --- | --- | --- |
| 每轮游戏开始时 | 全场进入新一轮的开始，不等于每个角色自己的回合开始 | `trigger: { global: 'roundStart' }`；手机 `noname/library/element/content.js` 的回合流程在增加 `game.roundNumber` 后触发 |
| 删除此项 | 对此角色在本局后续选择中移除该选项 | `player.storage.tyj_lunhui` 记录已选类别；参考手机界卞夫人 `zunwei` 的使用记录和选择过滤 |
| 觉醒技 | 达到该技能自身条件时进行觉醒的技能 | `juexingji: true`；例如志继 `zhiji`、若愚 `ruoyu`、魂姿 `hunzi` |
| 使命技 | 有使命目标、成功及失败等自身结算的技能 | `dutySkill: true`；手机手杀包例如 `pothuanshi`（还施）、`mbweiming`（威名） |
| 限定技 | 按原技能说明限制本局发动次数的技能，通常一次 | `limited: true`；例如奇谋 `qimou`、涅槃 `oldniepan` |
| 主公技 | 带主公技类别标记、按原技能及模式条件结算 | `zhuSkill: true`；例如护驾 `hujia`、激将 `jijiang`、救援 `jiuyuan` |

手机当前 `Player.hasZhuSkill` 检查技能拥有及相关阵营规则，获得主公技不需要把角色身份改成主公。轮回不改身份，也不绕过技能自身如同势力角色响应等要求。

同一个技能可有多个标记，例如同时属于觉醒技和主公技。它可在多个类别池中出现，但一旦已拥有，就不会再次作为候选。

## 技能池为什么单独构建

手机当前 `get.gainableSkills` 经 `lib.filter.skillDisabled` 筛选，后者会排除 `unique`、临时、子技能等类型。特殊类型经常带 `unique`，直接使用变幻的普通技能池会漏选。

轮回采用 `get.gainableCharacters` 的可用武将列表，遍历武将主技能并按四类标记分类；允许 `unique`，继续排除 Boss/特殊隐藏武将、装备技能、临时效果、子技能、已拥有或已消耗的技能，以及缺少名称或说明的技能。带 `ai.combo` 前置声明时要求当前已拥有前置技能。

各类别在一次发动时统一计算；同一技能在多个武将上出现仅计一次，抽取不因重复出现而加权。选择后再检查一次可获得性，避免选择期间其他结算已授予同一技能。没有把普通技能池的全局过滤规则改掉。

技能间的专属联动仍按原代码运行。依赖开局事件或未声明的其他技能的扩展技能，获取后的实际表现需要在对局中确认。
