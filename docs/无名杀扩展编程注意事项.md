整理日期：2026-10-15；最近更新：2026-11-03。

本文件为 GitHub 便携整理版，运行路径按仓库结构调整；原始备份和手机源码快照保留在维护者本地。

本文用于维护“汤圆精品包”中的神左慈移植项目，以及后续新增武将。内容结合当前工作区代码、手机框架只读参考、用户测试反馈和无名杀上游文档。不同本体、懒人包和 UI 扩展可能存在差异；后续编程应优先查看实际运行版本的源码。

## 2. 先看目标版本，再确定扩展结构

先查看目标本体的 `noname.js`、版本信息、扩展加载代码和能正常工作的武将示例，再选择 API。上游 `main` 可能比手机懒人包更新，不能把最新源码直接当成手机的实现。

本项目使用 ESM 入口：

```js
import { lib, game, ui, get, ai, _status } from "../../noname.js";

export const type = "extension";

export default function () {
    return {
        name: "shenzuoci_yizhi_v2",
        content(config, pack) {},
        precontent() {},
        package: {
            character: {
                character: {},
                translate: {},
                characterFilter: {},
                characterIntro: {},
                characterTitle: {},
            },
            skill: {
                skill: {},
                translate: {},
            },
            intro: "",
            author: "移植自汤圆精品包",
            version: "1.1.0",
        },
        files: { character: [], card: [], skill: [], audio: [] },
    };
}
```

重点检查：

- 武将定义放在 `package.character.character`，技能定义放在 `package.skill.skill`；翻译放在对应的 `translate` 中。
- 使用的角色和技能 ID 必须一致。比如武将技能数组写 `tyj_huanxing`，技能定义和翻译也必须使用这个 ID。
- 扩展目录名、入口 `name` 和 `info.json` 的 `name` 保持一致，中文显示名通过翻译或介绍处理。
- 本项目在采用 `package.character/package.skill` 的修复版后，用户已确认能找到神左慈。
- “扩展开着”只说明启用了扩展，不能证明武将和技能已经注册成功。
- `game.import("character", ...)` 在已读取的“天庭”扩展中也有使用；不能据此断言它在所有新版中无效。此前手动导入方案未解决本项目的显示问题，应以最终可用结构为准。
- 不要混淆 `lib.config.all.characters`（包列表）与 `lib.config.characters`（启用列表），也不要把它们直接当成 `connect_characters` 保存。联机和单机配置应按实际加载器分别处理。
- 自动写配置时，应去重、保留用户原有列表，并考虑用户主动关闭武将包的情况，避免每次启动强制恢复。

## 3. 把技能描述拆成事件、条件、选择和结算

写技能之前先列出四项：

1. 什么时候触发：受到伤害、出牌阶段、脱离濒死、角色死亡等。
2. 满足什么条件：是否存活、是否处于自己的出牌阶段、是否有可失去技能。
3. 玩家选择什么：是否发动、选择技能、是否允许取消。
4. 选择后如何结算：先支付代价，再执行效果；一次事件触发几次。

本项目涉及的事件：

| 事件 | 用途及注意点 |
| --- | --- |
| `damageEnd` | 每次伤害事件结束；若该伤害带本技能的 `_tyj_bianhuan_dyingHandled` 标记，跳过此时机，避免获救后重复 |
| `dying` | 濒死流程中的时机，不能当作“脱离濒死后” |
| `dyingAfter` | 濒死事件结束后的时机；要求“获救后”时还要核对存活、体力和事件条件 |
| `dieAfter` | 死亡事件后的时机；`global` 表示监听场上其他相关死亡事件 |
| `phaseUse` | 当前幻形使用的自己的出牌阶段；配合 `usable: 1` 限制每阶段一次 |
| `recoverEnd` | 回复体力的结算末段；旧版幻形曾使用，当前幻形已不再监听 |
| `phaseBefore` 配合 `game.phaseNumber === 0` | 当前“新生”使用的开局条件 |
| `enterGame` | 当前代码还覆盖中途进入游戏的情况 |

当前“变幻”的触发器为：

```js
trigger: {
    player: ["damageEnd", "dying", "dyingAfter"],
    global: "dieAfter",
}
```

当前保留进入濒死 `dying` 和获救后 `dyingAfter` 两个时机，每个时机各发动一次，技能说明已同步列出。`dyingAfter` 要求角色存活且体力大于 0，不将未获救的濒死事件当作获救。

重复排查：当前变幻没有监听 `recoverEnd` 或 `recoverAfter`。已核对[官方 v1.11.5.2 伤害与濒死流程](https://github.com/libnoname/noname/blob/v1.11.5.2/apps/core/noname/library/element/content.ts)，伤害先结算濒死子事件，原伤害之后才结束；因此 `dyingAfter` 和原伤害的 `damageEnd` 会在获救后接连到来。当前变幻在 `dying` 或 `dyingAfter` 分支的 `step 0` 中，仅给 `trigger.reason` 指向的、且属于技能拥有者的原始 `damage` 事件设置 `_tyj_bianhuan_dyingHandled` 标记，随后过滤它的 `damageEnd`。这里只核对了对应版本官方源码，未回读懒人包对框架的修改。

复查修正：不能直接用本体 `_dyinged` 过滤。它在调用 `player.dying(event)` 前设置，而该方法遇到 `player.nodying` 或已有濒死状态时可以直接返回，因此标记并不证明濒死分支实际执行过。改用本技能结算时记录的标记，可保留这些情况下正常的受伤触发；标记放在原伤害事件上，不影响下一次伤害或其他角色。

区分事件名和时机名：传入技能 `filter(event, player, triggerName)` 的 `event.name` 仍为 `damage` 或 `dying`；准确的 `damageEnd`、`dyingAfter` 应使用第三个参数 `triggerName`，不能通过比较 `event.name === 'damageEnd'` 判断。

技能描述的每个“可以”“锁定技”“一次”“每点”“非濒死”等限定都必须有对应实现。修改代码后，同时更新 `技能ID_info`。

## 4. “可以”必须允许玩家拒绝

“幻形”的用户设计：

> 出牌阶段限一次，你可以选择一个技能失去并发动一次变幻。

要求：

- “出牌阶段限一次”默认指拥有者自己的出牌阶段；当前实现使用 `enable: 'phaseUse'` 和 `usable: 1`，没有添加其他角色或每名角色的出牌阶段。
- 玩家不点击主动技能时不会发动；点击后可以在技能选择窗口取消，取消不会失去技能，也不会执行变幻。
- 玩家选择技能后，先失去选定技能，再执行一次变幻的三选一获得流程。
- 不要用 `forced: true` 强迫主动技能发动。主动技能本身已经通过出牌阶段的技能按钮提供“可以发动”的选择。
- 当前候选排除变幻、幻形自身及变幻的 `flash` 子技能。
- 候选列表使用 `player.getSkills(null, false)`，因此不读取装备技能并保留框架的技能过滤；同时排除 `player.tempSkills`、`player.additionalSkills` 以及带有 `temp`、`sub`、`charlotte`、`unique`、`hiddenSkill` 标记的技能，覆盖加强主公和特殊身份提供的临时技能。
- 候选按显示翻译名去重，并优先保留武将牌原有技能；这样即使某个临时效果错误地复用了技能 A 的显示名，也不会和真正的技能 A 同时出现在选择框。
- AI 的默认选择和玩家选择是两件事。当前幻形 AI 固定返回 `cancel2`，意味着 AI 默认取消，需要时再单独设计策略。

## 5. 复用技能效果时，不要直接执行事件函数

“发动一次变幻”在本项目中指：随机展示至多三个候选技能，玩家选一个获得。它不包含重新执行“新生”、制造雷伤或回复体力。

建议让变幻与幻形调用同一段三选一效果，避免分别复制后产生差异。可使用目标版本支持的事件调用方法，或提取共享的异步结算函数。

- 旧式 `"step 0"` / `"step 1"` 依赖游戏事件编译与调度，不能像普通函数一样直接调用 `lib.skill.xxx.content()`。
- 带有 `"step 0"` 等标记的 `content` 会经过 `StepCompiler` 重新编译成新函数。步骤代码不能引用扩展工厂外层的局部函数；候选计算等辅助函数必须定义在步骤内，或通过编译后仍可访问的框架对象调用。
- 新写技能可参考上游 [Async 指南](https://github.com/libnoname/noname/blob/main/docs/async-guide.md)，使用 `async content(event, trigger, player)` 和事件结果 API；具体签名以手机版本为准。
- 当前幻形使用 `player.useSkill("tyj_bianhuan")` 并以 `await` 等待子事件，用户已反馈幻形不再报错。后续更换调用方式时仍需复测，不能只靠语法检查认定有效。
- 禁止静默吞掉错误来“保证不报错”。当前幻形已移除旧版静默 `try/catch`；若变幻子事件失败会暴露错误，方便定位支付代价后未执行效果的问题。
- 除非设计需要，不要给出牌阶段发动的技能随意加 `forceDie`。
- 玩家界面、AI、托管以及联机都需要可完成的结算路径；只有本机点击能用不够。

## 6. 获取、失去技能时要处理候选池和辅助技能

写随机获得技能时，应检查：

- 候选技能必须存在、可获得、属于已加载内容，且有可显示的名称和说明。
- 排除玩家已经拥有的技能；候选不足三个时允许少于三个，为空时安全结束。
- 需要排除辅助子技能、装备技能等哪些类型，应依照设计和目标 API 确定。
- 显示候选窗口前完成过滤，避免抽到没有说明的技能后窗口没有可点击选项。

当前旧逻辑含有：

```js
list.remove(player.getSkills());
```

不要假定 `remove` 能接收数组并逐个移除；应核对本体的数组扩展实现，或使用原生过滤。例如：

```js
const owned = new Set(player.getSkills());
const candidates = get.gainableSkills().filter(skill => !owned.has(skill));
```

写“选择一个技能失去”时：

- 玩家看到的候选应是可以按设计失去的技能，不能把后台辅助子技能当成独立技能。
- 按当前设计，幻形候选必须排除变幻、幻形及变幻的 flash 辅助技能，防止失去武将的核心机制。
- 当前幻形不会提供幻形自身作为代价；点击选择后可以取消，不失去任何技能。
- 若失去的是此前变幻获得的技能，应同步核对 `tyj_huashen_gained` 等记录，避免头像闪现继续引用已失去或不存在的技能。
- `flashAvatar` 的参数和技能对应武将映射要按目标版本检查，技能 ID 不一定等于头像需要的武将 ID。

## 7. 头像、语音、皮肤按文件内容核对

当前使用的资源：

```text
character/tyj_zuoci.jpg
audio/skill/tyj_bianhuan1.mp3
audio/skill/tyj_bianhuan2.mp3
audio/skill/tyj_bianhuan3.mp3
audio/skill/tyj_bianhuan4.mp3
```

对应引用示例：

```js
"ext:shenzuoci_yizhi_v2/character/tyj_zuoci.jpg"
"ext:shenzuoci_yizhi_v2/audio/skill:4"
```

新版技能语音的 `audio` 路径写成 `ext:<扩展名>/audio/skill:<句数>` 时，引擎会按当前技能名和编号查找 `audio/skill/<技能名>1.mp3`、`<技能名>2.mp3` 等文件。若把技能名再写进路径，解析器会继续拼接技能名，实际会寻找错误的重复路径。迁移时应让 `audio` 字段、技能 ID、文件名前缀三者一致，并把 `files.audio` 写成相对路径清单。

本次语音不播放的原因已经确认：移植代码原先写成了 `ext:shenzuoci_yizhi_v2/audio/skill/tyj_bianhuan:4`，引擎会在这个路径后再次拼接技能名，导致实际查找重复的技能名前缀。最终修正为 `ext:shenzuoci_yizhi_v2/audio/skill:4`，对应根目录下的四个 `tyj_bianhuan数字.mp3` 文件。新版上游的技能音频解析还会把带编号的 `audio` 转换为逐个文件地址，因此不能只检查字段是否存在，还要按解析后的最终路径核对文件。

- 不能仅凭文件扩展名判断格式：`tyj_zuoci.jpg` 的文件头实际是 `GIF89a`。
- 该 GIF 原始字节已被复制；没有转成静态图。是否在当前 UI 中持续播放，需要实际查看。GIF 动图和十周年 UI 的骨骼动皮不是同一套资源机制。
- 不要因为后缀是 `.jpg` 就断言必须改名才能播放，先检查渲染器怎样加载图片。
- 当前旧包及压缩包中没有找到 `tyj_zuoci.mp3`；旧代码里存在通用阵亡语音调用，不能证明实际音频存在。
- 不用其他武将的阵亡语音冒充原素材，不虚构未找到的皮肤和台词。
- 修改资源目录后必须同步代码路径；`files` 清单也要按实际导入器的路径约定检查，不能认为声明清单就能凭空生成资源。

## 8. 修改、备份、传输和恢复

每次修改：

1. 确认正在改本地新扩展，还是旧包主文件。默认保留旧包主文件作为参考。
2. 备份要修改的 `extension.js`、`info.json` 或其他具体文件，记录时间、长度和 SHA-256。
3. 扩展内部版本号与 `info.json` 版本号同步更新。
4. 完成本地验证后，交由用户手动替换手机文件。
5. 完全退出并重启游戏，确认加载的是新版本。

文件应保存为 UTF-8。Windows PowerShell 向 Python 管道传递中文曾出现 `????`，所以优先使用支持 UTF-8 的直接文件编辑方式；写完检查中文武将名和说明。

MTP 注意事项：

- 本次传输出现过复制后文件未实际更新、覆盖被跳过等问题；不能根据复制调用返回成功就认定部署成功。
- 检查实际目标目录，必要时把手机文件回读到新的本地目录，与源文件比较 SHA-256。
- 此前中文目录中的 `extension.js` 传输异常只是本次观察，不要写成“MTP 一律不能使用中文目录”。
- 当前用户要求手动处理手机文件，不再尝试用界面或脚本代替用户删除、重命名或覆盖。

恢复时只还原对应备份文件，避免覆盖其他扩展或玩家配置。

## 9. 验证顺序与当前验证状态

先做本地检查：

```powershell
node --check ".\shenzuoci_yizhi_v2\extension.js"
Get-FileHash -LiteralPath ".\shenzuoci_yizhi_v2\extension.js" -Algorithm SHA256
```

语法检查通过只证明 JavaScript 可解析，不证明无名杀事件调用、选项和技能结算正确。

手机实战检查：

| 检查项 | 预期 |
| --- | --- |
| 扩展启用并重启 | 搜索能找到神左慈、神左慈改 |
| 普通伤害 | 每次符合条件的伤害事件执行对应变幻 |
| 进入濒死 | 发动一次变幻 |
| 获救脱离濒死 | 发动一次变幻，原伤害的 `damageEnd` 不再追加一次 |
| 普通回复体力 | 不触发变幻 |
| 再次进入并获救 | 新的濒死流程在进入和获救时仍各发动一次 |
| 未获救死亡 | 不把失败的濒死结算误当作“脱离濒死获救” |
| 自己的出牌阶段发动幻形 | 可以选择一个可失去技能，再完成一次三选一 |
| 同一出牌阶段第二次发动 | 不再提供第二次发动机会 |
| 非自己的出牌阶段 | 不能发动幻形 |
| 发动幻形后取消技能选择 | 技能不减少，不执行三选一 |
| 装备带来的技能 | 不出现在幻形选择框 |
| 加强主公或特殊身份带来的临时技能 | 不出现在幻形选择框 |
| 变幻、幻形及内部子技能 | 不出现在幻形选择框 |
| 没有候选或不足三个 | 安全结束或展示实际数量，不出现空窗口卡住 |
| AI、托管 | 能取消或完成选择，无永久暂停 |

截至本文整理：

- 用户已确认结构修复后神左慈能够出现在游戏中。
- 当前本地已增加 `dyingAfter`、神左慈改和幻形。
- 当前本地已修正变幻技能语音路径，并保留四个原始 MP3；代码语法检查、JSON 检查和四个音频文件的格式检查均已通过。
- 用户已反馈变幻技能语音可以正常引用。

## 11. 轮回：轮开始、分类技能与删除选项

详细研究、手机文件路径和原始依据见 [轮回技能设计与术语](轮回技能设计与术语.md)。

- 轮开始使用 `trigger: { global: 'roundStart' }`，不能用自己的 `phaseBegin` 替代。本体决定何时进入新一轮，包含第一轮；不要再添加开局事件造成首轮重复。
- 分类字段分别为 `juexingji`、`dutySkill`、`limited`、`zhuSkill`。获得技能不等于自动觉醒、完成使命或无视原条件。
- 普通 `get.gainableSkills` 会经 `lib.filter.skillDisabled` 排除 `unique`，不适合直接当作轮回技能池。当前以 `get.gainableCharacters` 提供的武将池为基础，从武将主技能取样，按标签筛选并保留 `unique`。
- 同一技能出现在多个武将上，抽样前按 ID 去重；排除已拥有、已消耗、内部、装备和缺少说明的技能。带 `ai.combo` 的技能需要已拥有其前置技能。
- 删除选项以 `player.storage.tyj_lunhui` 的类别记录实现：先完成 `await player.addSkills`，再记录删除；取消、空池和获取失败不删除。没有设置清空记录的 `onremove`，防止失去再获得刷新选项。
- 轮回为 `Async Content`，候选和类别选择都使用本体 `chooseControl(...).forResult()`；三选一界面展示技能名称及说明，候选不足三个时展示实际数量。
- 本地测试：`node tests/lunhui-runtime.cjs`；手机源码数据核查：配置 `NONAME_PHONE_SNAPSHOT` 后运行 `node tests/lunhui-phone-catalog.cjs`，见 [测试说明](../tests/README.md)。后者只载入本次六个包的源码快照，并模拟禁将筛选；不代表手机当前启用包的实时状态。
